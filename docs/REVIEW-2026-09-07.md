# Code review and Shopify feature coverage

This document records the initial review. See [current implementation coverage](PARITY.md) for the subsequent changes.

Date: 2026-09-07. Repository: `alex-brecher/shopify-multi-store`.
Base: GitHub `main`, commit `e771905`, package version `1.5.1`.
Review branch: `codex/review-parity-20260907`.

## Result

The review found three reliability defects. The local branch contains fixes and regression tests for all three.
The branch does not add the full Shopify feature set. The feature matrix defines that work.
No store data, credentials, scopes, installed runtime, GitHub branch, or public package changed during this review.

The review covered request transport, OAuth, configuration, pagination, report aggregation, tool registration, setup helpers, tests, and release workflows.
It was a source review with mocked API tests. It was not a penetration test or a live Shopify acceptance test.

## Fixed defects

### P1: GraphQL failures appeared as successful tool calls

In `src/index.ts`, the generic tools treated an HTTP 200 GraphQL response as success, even when its `errors` array contained failures.
The multi-store query also counted these stores as successful. An access-denied response therefore increased the success count.

Single-store queries, mutations, and shop-info calls now set `isError: true` for top-level GraphQL errors.
Multi-store queries now report the correct per-store status and success counts.
Partial data and error details remain available. A partial response must not trigger an automatic mutation retry.

Regression coverage includes access-denied queries, mutations, and two-store error counts through the MCP transport.

### P2: Response bodies escaped the request timeout

Four HTTP helpers stopped their abort timers after response headers arrived. A stalled response body could keep a call open indefinitely.
The affected paths were Admin GraphQL, client-credentials OAuth, authorization-code exchange, and setup token verification.

All four now read the response body before they stop the timer.
A regression test simulates headers followed by a stalled body for each helper.

### P2: Pagination missed cursor cycles

The pagination guard rejected consecutive duplicate cursors but accepted cycles such as A, B, A.
Empty pages in such a cycle did not increase the existing size counter. The loop could continue indefinitely.

Both connection pagination and nested product-variant pagination now track all cursors within the scan.
The MCP regression test supplies empty pages with a three-response cycle and asserts that the scan fails after three requests.
Nested variant pagination uses the same cycle rule, but lacks a separate cycle fixture.

## Remaining issues and optimization work

1. Mutation payload `userErrors` need separate handling. The current fix covers top-level GraphQL errors only.
   A mutation can return HTTP 200 with no top-level errors and still reject the requested change.
   Add schema-aware payload handling, including aliases and fragments. Preserve partial results, and never retry a partial write automatically.
2. The query/mutation guard examines the document prefix with a regular expression.
   Valid fragment-first documents fail. Replace this guard with an AST parser and enforce exactly one operation of the expected type.
   This review did not demonstrate a mutation bypass against Shopify.
3. Throttle retries use fixed exponential delays when `Retry-After` is absent.
   Add cost-aware delays from `requestedQueryCost`, `currentlyAvailable`, and `restoreRate`, with bounded waits and jitter.
   Share a limiter by store and app identity. Independent stores can remain concurrent.
4. Output limits measure compact JSON, but MCP text uses indented JSON and also includes structured content.
   Use compact text serialization to reduce duplicate output volume. Define whether each limit applies to data or the full MCP response.
5. Large scans request 250 rows and can hit the 50,000-character page limit before the report-level limit.
   Use smaller adaptive pages. For full exports, add resumable bulk-operation workflows with explicit completeness and failure states.
6. The input schema accepts at most ten explicit stores, while two tools can include all configured stores when aliases are omitted.
   Remove this inconsistency with a shared bounded-concurrency selector. Preserve explicit store identity on writes.
7. Some report totals derive from a bounded sample. Keep completeness, currency, access errors, and count precision visible in every UI.

Shopify's preview tool produces previews that users can claim as new stores. It cannot apply those previews to an existing store.
This review found no documented public Admin API equivalent for that complete workflow. Treat exact parity as an access dependency, not an implementation promise.
Sample-product widgets, charts, image references, and preview cards also need host UI support. JSON tool wrappers alone do not reproduce those experiences.

## Shopify repositories to use

| Repository | Recommended use | Integration decision |
|---|---|---|
| [Shopify/shopify-app-js](https://github.com/Shopify/shopify-app-js) | `@shopify/admin-api-client` and `@shopify/api-codegen-preset` | Pilot typed operations first. Preserve alias routing, credential isolation, timeout behavior, and mutation retry rules. |
| [Shopify/Shopify-AI-Toolkit](https://github.com/Shopify/Shopify-AI-Toolkit) | Documentation, schemas, GraphQL validation, and ShopifyQL guidance | Extend the existing companion integration. Pin or audit versions and state telemetry behavior. |
| [Shopify/cli](https://github.com/Shopify/cli) | App and theme development workflows | Keep outside the core reporting runtime until app or theme tooling enters scope. |
| [Shopify/shopify-app-template-react-router](https://github.com/Shopify/shopify-app-template-react-router) | A future embedded Shopify Admin interface | Use only if the product expands from a local MCP server to a hosted app. |
| [Shopify/shopifyql-py](https://github.com/Shopify/shopifyql-py) | Reference analytics behavior | Keep the TypeScript runtime. A Python dependency adds little value to this server. |

The current installer already selects `shopify-admin` and `shopify-shopifyql` from Shopify-AI-Toolkit.
The current upstream repository contains both skills.

## Recommended delivery order

1. Complete mutation outcome handling, AST guards, schema tooling, and store capability discovery.
2. Add product, collection, order, customer, discount, inventory, and media workflows from the matrix.
3. Add ShopifyQL tables and charts, cost-aware throttling, and resumable exports.
4. Add sample-product and preview experiences after API access and host UI support are established.

Every write workflow needs exact store identity, bounded input, the granted scope, user authorization, payload-error handling, and readback.
Inventory writes need concurrency protection. An HTTP timeout after a mutation leaves its outcome uncertain and must not cause blind replay.
